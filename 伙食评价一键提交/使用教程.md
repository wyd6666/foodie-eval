## 1. 这东西到底怎么工作的

不用装 App，不碰手机。脚本直接跟服务器说话，走的是 App 里那套一模一样的接口：

```
登录（账号密码先 AES 加密再发）
  → 问服务器「今天我要评什么」（拿到 10 道满意度题 + 10 道监督题）
  → 每道题都选最高档（满意 / 2 分）
  → 提交
```

所以：

- **不用你的手机也能跑**，放办公室电脑、甚至放 NAS 上定时跑都行
- **交出来的结果和你手点完全一样**，因为提交的就是同一套数据
- 一天只能交一次的账号，第二次会自动跳过，不会报错也不会重复

## 2. 第一次使用：双击一次就完事

**Windows**：把名单文件（一行一个 `姓名 账号 密码`）放到这个文件夹，双击 **`一键评价.bat`**
**Mac / Linux**：终端里执行 `./一键评价.sh`

它会自己把能做的都做掉：

```
==============================================
 伙食评价 · 一键提交
==============================================
✓ 依赖检查通过
✓ 服务器: sd.example.gov.cn
✓ 名单: accounts.json（13 人）

--- 预演（只登录和算分，不会提交）---
[1/13] 张三  ✓ 预演通过（10满意度+10监督）
...
预演结果：能交 13 人 | 今天已交 0 人 | 有问题 0 人

按回车开始提交（Ctrl+C 取消）：
--- 提交中 ---
[1/13] 张三  ✓ 提交成功（10满意度+10监督）
...

==============================================
 完成
==============================================
交上了 13 人
明细记录：out/batch_20261028_021936.json

全部搞定。
```

**你只需要做两件事**：

- 第一次：输一次服务器地址（它会记住，写进 `eval_config.json` 和 `out/.last_host`，以后不再问）
- 每一次：按一下回车

依赖缺了会自动装，名单会自动找（`accounts.json` → 任何 `*.txt` → `*.csv` → 都没有就问你输），
找不到服务器地址会告诉你手机上在哪看。这些都不需要你记命令。

### 它会自己挡住重复提交

今天已经交过的人不会再交一次，记在 `out/submitted.json` 这个台账里。所以：

| 情况 | 双击一键评价后 |
|---|---|
| 今天已经交了，中午又手滑点一次 | 「今天这些人都已经交过了，没有要做的」——**一条都不会重复交** |
| 交完之后又新来了两个人 | 只交这 2 个新人，老人自动跳过 |
| 有人密码改了 | 显示「✗ 账号或密码错误」，其它人照常交 |

想强制重交（比如确实要再交一次），加 `--force`：

```bash
./一键评价.sh --force
```

### 只想看看，不想提交

```bash
./一键评价.sh --dry
```

只预演，打印「能交几人 / 已交几人 / 有问题几人」就退出。

## 2.5 或者：用网页版，鼠标点两下

不想碰命令行的，用网页版最直观。

**Windows**：双击 `网页版.bat`（浏览器会自动打开）
**Mac / Linux**：`./网页版.sh`，然后浏览器打开 `http://127.0.0.1:8080`

页面就四个区块：

```
① 服务器地址   填一次，之后自动记住
② 名单         直接把 Excel/txt 拖进去，或粘贴；一行一个人，三种写法都认
③ 开始         [先预演（不提交）]  [直接提交]
④ 结果         每交一个实时冒一行：姓名 / 账号 / 机构 / 状态 / 说明
```

页面上的好处：

- **实时进度**：不用等全部跑完，谁交上了立刻看见，进度条和成功/跳过/失败计数一起走
- **先预演再提交**：预演不会碰服务器数据，看清楚「能交几人 / 已交几人 / 有问题几人」再按提交
- **重复提交自动挡住**：今天交过的人页面顶部会提示「今天已经有 13 个人交过了」，这些人自动跳过
- **拖动文件**：不用先跑导入命令，直接把 `账号密码.txt` 拖到虚线框里
- **坏行会标出来**：哪一行格式不对，页面会直接告诉你行号
- **可设提交间隔**：怕服务器把连续提交当成爬虫，就调「每个账号间隔」（见下）
- **敏感内容默认遮住**：名单框不编辑时是糊的，预览和结果里的姓名/账号/机构都打码，点一下才显示原文


### 每个账号间隔（防被当爬虫）

「③ 开始」按钮下面有一行：

```
每个账号间隔  [ 0 ] 秒   0 = 不等待（最快）；想更像人工操作就填 30~50 秒
```

- 填 **0** → 几个人同时发，13 个人十几秒跑完
- 填 **30~50** → 一个交完再交下一个，节奏接近人手点击
- 填了间隔会**自动改成一个个来**（并发模式下讨论间隔没意义）
- 每次等待会随机上下浮动 20%，固定节拍反而更像脚本

提交前会告诉你大概要多久：

```
将向 sd.example.gov.cn 提交 13 人的评价，确定吗？

每个账号间隔 40 秒，预计用时约 8.7 分钟。
```

**建议值**：内网服务器一般不用管（填 0 就行）；如果发现服务端开始拒绝或变慢，改成 30~50 秒最稳。

命令行也支持：

```bash
bash run.sh batch -a accounts.json --interval 4
```

### 想在别的电脑/手机上打开

**同一个 WiFi 里**（局域网）：

```bash
./网页版.sh --host 0.0.0.0 --password '设个密码'
```

别人的手机访问 `http://你的IP:8080`，输密码即可。

> 加 `--host 0.0.0.0` 必须同时设 `--password`，否则服务会拒绝启动 —— 这是防呆。

> 这个网页里传的是**明文账号密码**，所以**只在局域网用**。
> 不要做端口映射、不要挂到公网 —— 需要给不在同一网络的人用时，另想办法（比如让对方连单位 VPN 进来）。

## 3. 手动分步（需要时看）

### 预演（不会提交）

```bash
bash run.sh batch -a accounts.json --dry-run
```

只登录、取题目、算好分数，**不会真的提交**。输出长这样：

```
[1/13] 穆也   ✓ 预演通过（10满意度+10监督）   (XX市消防救援支队XX站)
[2/13] 姚磊   ✓ 预演通过（10满意度+10监督）   (XX市消防救援支队XX站)
汇总: 成功 13 | 跳过 0 | 失败 0 | 共 13
```

看到「预演通过」，说明账号密码对、能拿到题目、分数算好了。

### 真提交

```bash
bash run.sh batch -a accounts.json
```

```
[1/13] 穆也   ✓ 提交成功（10满意度+10监督）   (XX市消防救援支队XX站)
...
汇总: 成功 13 | 跳过 0 | 失败 0 | 共 13
报告: out/batch_20261028_021936.json
```

### 查交没交

```bash
bash run.sh batch -a accounts.json --status
```

```
[1/13] 穆也   ✓ 本机构本周 18 条记录（按机构统计，非个人）
[12/13] 牛天宇 ✓ 本机构本周 1 条记录（按机构统计，非个人）
```

> ⚠️ 这里的条数是**整个机构**的，不是这个人自己的。因为这个查询接口是按机构 ID 查的，
> 同一个大队的人看到的是同一份数字。要看某人今天交没交，跑一次 `--dry-run`：
> 显示「跳过：服务端没下发任务」就是今天已经交过了。

## 4. 名单怎么准备

### 从 Excel 来

Excel 里排成三列 `姓名 | 账号 | 密码`，另存为 CSV，然后：

```bash
bash run.sh import 名单.csv --format name-first
```

### 支持的格式

| 格式 | 例子 | 用不用加参数 |
|---|---|---|
| 账号=密码=姓名 | `370101199001011234=Passw0rd.=张三` | 不用 |
| 逗号分隔 | `370101199001011234,Passw0rd.,张三` | 不用 |
| 姓名在最前 | `张三,370101199001011234,Passw0rd.` | 加 `--format name-first` |
| 制表符分隔 | 从 Excel 直接粘贴出来的 | 不用 |

姓名中间的空格会自动去掉（`张  三` → `张三`），重复的账号只保留第一个。

### 顺便验一遍密码

```bash
bash run.sh import 账号密码.txt --check
```

会挨个登录一次，把密码错的挑出来：

```
    ✓ 穆也        XX市消防救援支队XX站
    ✗ 某某        账号或密码错误
验证结果: 通过 12 / 13
```


### 后续加人 / 删人（不用重做整份名单）

名单会变，所以不用每次重新导一遍，直接增量改：

**加一个人**

```bash
bash run.sh add 张三 370101199001011234 Passw0rd.
```

```
    + 张三     370101199001011234
[✓] 新增 1 人，更新 0 人，现在共 14 人 -> accounts.json
    备份: accounts.json.bak
```

**一次加一批**（准备一个 txt，一行一个人，`账号=密码=姓名` 或 `姓名 账号 密码` 都行）

```bash
bash run.sh addfile 新人.txt
```

**看现在有哪些人**

```bash
bash run.sh list            # 密码自动打码
bash run.sh list --check    # 顺便挨个登录验证密码
```

```
accounts.json: 共 13 人
  序号  姓名      账号                    密码
  1   穆也      370481198909080939    TQ******
  2   姚磊      320721198402060032    TQ******
```

**删人**

```bash
bash run.sh del 张三                  # 按姓名
bash run.sh del 370101199001011234    # 按账号
bash run.sh del 张三,李四             # 一次删多个
```

**Windows 用户**：双击 `win-加人.bat` / `8-看名单.bat` / `9-删人.bat`，
`7-加人.bat` 会一行一行问你，格式 `姓名 账号 密码`，加完按两次回车结束。

三个要点：

1. **自动去重**：同一个账号再加一次不会变成两条，会更新成最新的姓名和密码（屏幕上标 `~`）。所以改了密码直接再 add 一次就行。
2. **自动备份**：每次改动前都会把旧名单存成 `accounts.json.bak`。删错人、加错人，把 `.bak` 改名复制回去就恢复了。
3. **不会丢数据**：读写是原子的（先写临时文件再替换），中途断电也不会把名单写坏。

## 5. 结果怎么看

三种状态，含义不一样：

| 状态 | 含义 | 要处理吗 |
|---|---|---|
| `✓ 提交成功` | 交上了 | 不用 |
| `· 跳过` | 服务端没下发任务（今天已交 / 不在用餐评价时间窗） | 不用，这是正常的 |
| `✗ 账号或密码错误` | 密码不对 | 改密码 |
| `✗ 提交被拒` | 其它业务拒绝 | 看 `out/*.log` |

**关键：`跳过` 不是失败。** 一天只能交一次的账号，第二次跑一定是「跳过」，汇总里单独计数，不会让整个批次变红。

每跑一次会留两个文件：

- `out/batch_<时间>.json` — 逐人明细，可以当台账存档
- `out/batch_<时间>.log` — 完整请求过程，出问题给懂技术的人看这个

## 6. 让它每天自动交

这批人的任务是按饭点下发的（一天可能有早/中/晚多次），所以推荐「**每天几个固定时间试一次，有任务就交，没任务就跳过**」。

**Linux / NAS / Mac**：执行 `crontab -e`，加一行：

```cron
0 7,11,17 * * * cd /你的路径/伙食评价一键提交 && python3 scripts/hqhs_batch.py -a accounts.json >> out/cron.log 2>&1
```

**Windows**：用「任务计划程序」新建一个任务，操作填

```
程序:   python
参数:   scripts\hqhs_batch.py -a accounts.json
起始于: D:\你的路径\伙食评价一键提交
```

触发器设成每天 7:00、11:00、17:00 各一次。

## 7. 出问题了怎么查

| 屏幕上看到 | 意思 | 怎么办 |
|---|---|---|
| `缺 host` | `eval_config.json` 里 host 没填 | 填上服务器地址 |
| `Connection refused` / 超时 | 电脑连不上内网服务器 | 换到能上内网的电脑；或先 ping 一下 host |
| `账号或密码错误` | 密码不对 | 用 `--check` 找出是哪个 |
| `跳过：服务端没下发任务` | 今天已经交过 / 不在时间窗 | 正常，不用管 |
| `跳过：当天评价次数已达上限（视为已交）` | 服务端拦了重复提交 | 正常，说明之前已经交上 |
| `详情返回空` / `题目列表为空` | 同上，没任务 | 正常 |
| `Token 无效或已过期` | 登录态失效 | 脚本每次都会重新登录，一般见不到 |
| 中文显示成乱码 | Windows 控制台编码 | 执行 `chcp 65001` 后重试 |

实在搞不定，把 `out/batch_<时间>.log` 最后 30 行发出来，照着能定位。

## 8. 安全提醒

1. **`账号密码.txt` 是明文**，里面是身份证号 + 密码。用完就删，别放网盘、别发群里。
2. `accounts.json` 同样是明文。如果电脑多人共用，建议跑完把名单文件也删掉，下次要用再导入。
3. `out/*.log` 里只有账号和机构名，**不含密码**，但也是敏感信息，别随便外发。
4. 这个包不要连同名单一起转发给别人 —— 只发脚本部分是干净的（名单是单独的文件）。

## 9. 另一种玩法：手机上点一下

如果你更希望「在手机上点一下就好」，包里有改好的 APK 方案：

```bash
bash run.sh autoeval apk/base.apk submit
```

生成的 `hqhs-autoeval-submit.apk`，装到手机上以后，进「伙食评价 → 新增评价」页面，
题目一加载就自动全选最高分并提交 —— 全程不用点。

注意两点：

- 签名变了，装之前必须先卸载原来的 App（**卸载前记下 App 里填的服务器地址**）
- 只对 `com.xykj.hqhs` v4.16.2 这个版本有效，App 升级后要重新打

如果不想卸载重装，直接用网页版或命令行 —— 不碰手机，也不用 root。

bash run.sh batch -a accounts.json --retry 2          # 网络失败重试
bash run.sh hqhs --status                     # 单人：查状态

bash run.sh autoeval apk/base.apk submit      # 打改包（手机上自动评价）
